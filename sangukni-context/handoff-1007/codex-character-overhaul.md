# 캐릭터 스킬·밸런스 전면 재작업 — Codex 전달 명세 (기준 2e04f7f)

**대상: 85종 전원.** 6장 표가 영웅별 작업 목록이다. 2장(사용자 직접 지시)이 있는 영웅은 2장이 우선한다.

이 문서는 영웅이 추가될 때마다 늘어나는 문서입니다. 지금은 0장(원칙), 1장(공통 작업), 2장(여포·관우)이 확정입니다. 나머지 83명은 3장 규칙을 따릅니다.

> **[최신] 영웅별 스킬 내용의 정본은 `character-skills-v9.md`입니다 (85종 0성/3성/5성, 사용자 승인).**
> - 이 문서의 2장(여포·관우)과 6장(시트 대비 작업표)에 있는 **목표 수치·효과는 v2 문서가 우선**합니다.
> - 6장은 '현재 코드가 어디에 있는지' 찾는 용도로만 씁니다.
> - 0장(원칙), 1장(공통 작업), 5장(검수)은 그대로 적용합니다.
> - v2 문서의 0장(등급 배율, 상태이상 표준, 설명문 규칙)도 공통 작업에 포함합니다.

## 0. 원칙 (사용자 결정)
1. **기준은 하나다.** 우선순위는 다음과 같다.
   - ① 사용자가 직접 준 영웅별 지시 (이 문서 2장)
   - ② 캐릭터 시트 v8 「스킬 요약」 (`캐릭터_스킬_성급표_v8_85종`)
   - 위 둘에 없는 기존 기획서(`삼국냥전_캐릭터기획_v3.xlsx`), 10-02 승인 수치(`approvedCharacterBalance.ts`), 레거시 계수표는 근거로 쓰지 않는다.
2. **9명 예외를 없앤다.**
   - 대상 파일: `src/data/releaseRuntimeCharacterText.ts`
   - 내용: "2026-10-02 user decision: retain nine heroes' live effects"
   - 사용자는 이 결정을 한 기억이 없다. 대상 9명(여포·마초·장비·동탁·화웅·황충·주유·태산(m1)·단아(m5))도 ①·② 기준으로 다시 구현한다.
3. **스킬 단계는 0성(기본) / 3성 / 5성 세 가지다.** 승급 단계(`promotionStage`, 0~5)가 0 이상이면 기본, 3 이상이면 3성, 5면 5성 효과를 켠다. 1·2·4단계에는 새 효과가 없다(능력치 상승만).
4. **설명문과 실제 효과는 같은 데이터에서 나온다.** 영웅마다 스킬 정의 한 곳(계수·지속시간·대상 수·단계별 추가 효과)을 두고, 전투 코드와 화면 설명문이 모두 이것을 읽는다. 설명문을 따로 손으로 쓰지 않는다.
5. **범용 3성 "+5%"를 없앤다.**
   - 위치: `contentBattle.ts:178` `template.kit!=='named'&&promotion>=3 → n*=1.05`
   - SR 이하 42칸을 시트의 개별 3성 패시브로 바꾼다.
6. **필드와 콘텐츠는 같은 스킬 정의를 쓴다.** 지금 구조(`castFieldSkill` → `contentBattle.cast`)를 유지하되, 영웅별 하드코딩(`fieldSkills.ts:119-121`의 영웅 id 분기 등)은 스킬 정의의 범위·대상 규칙으로 옮긴다.

### 2-1. 여포냥 (yeo) — SSR · 물리 근접 · 군웅
**스킬 (시트 v8 기준으로 재구현)**
| 단계 | 효과 | 현재 코드 (`contentBattle.ts:614-620`) |

| 0성 | 넓은 범위의 적에게 도약해 내려찍는다. 주변 적에게 **공격력 480% 피해**. 착지 지점에 **4초간 용암 지대**를 만들어 **초당 40% 피해** | 105% (대상 1명이면 ×1.35) + 화상 30%/초 + 자신 보호막 15% |

  - 같은 여포의 장판이 겹치면 피해는 하나만 들어간다.
- **[결정 필요] 3성 화상 수치.** 사용자 지시에 숫자가 없다. 제안: 초당 공격력 20%, 3초, 중첩 없음(갱신). 기존 화상(30%/4초)보다 낮게 잡은 이유는 0성 용암과 겹치기 때문이다.
- 치명타 상태 키(`crit`, `critDamage`)는 이미 있다(`contentBattle.ts:51, 123`).

**모션**
- 평타 모션을 교체한다. 지금은 봉으로 찌르는 느낌이다. **방천화극을 크게 휘두르는 베기**(옆으로 반원)로 바꾼다.
- 원화(프레임)가 새로 필요하면 원화 담당 요청 목록에 올리고, 그 전까지 기존 프레임 순서로 대체할 수 있는지 먼저 확인한다.

**스킬 연출**

- 수정
  1. 시전 시작 때 착지 지점 = `yeoImpactArea` 중심을 확정해 저장한다.
  2. 도약 연출 동안 여포를 그 지점으로 이동시킨다. 멀리 뛰는 포물선이고, 착지 시각은 `fieldSkillTiming.ts:15`의 contact .68이다.
  3. 착지 순간 그 지점에 범위 원·충격 연출·용암 장판을 같은 중심으로 그린다(`poc/fieldView.ts:835-838`).

### 2-2. 관우냥 (gwan) — SSR · 물리 근접 · 촉
**스킬**
| 단계 | 효과 | 현재 코드 |
|---|---|---|
| 0성 | 전방으로 돌진하며 **3번 베어 공격력 총 600% 피해** (200%×3) | 160%×3 = 480% (`gwanSkill.ts:4`) |
| 3성 | 피해 입은 적은 **5초간 방어력 20% 감소** | 마지막 타격 후 방어 -20% 5초 (0성부터) |
| 5성 | **방어력 무시 + 적 버프 2개 해제** | 방어 감소 대상에게 피해 +25% (`contentBattle.ts:177`) |

- 3성 방어력 감소
  - 3번의 타격 중 하나라도 맞은 적에게 건다. 0성에서는 걸지 않는다.
  - 현재 '방어력 감소'는 받는 피해 +20%로 동작한다(`contentBattle.ts:179` `defenseDown`). 이 의미를 유지한다.
- **5성 "방어력 무시"는 다른 효과로 바꾼다 (사용자 결정).** 지금 엔진은 적에게 방어력 값이 없어서 글자 그대로 구현하면 효과가 0이다.
  - **제안 (사용자 확인 필요):** **방어력이 감소한 적에게 주는 관우의 피해 +30%** + 적 버프 2개 해제.
  - 이유: 3성 방어 감소와 연결되고 지금 엔진에서 바로 동작한다. 기존 5성(+25%)보다 조금 강하다.
  - 설명문: "방어력이 감소한 적에게 주는 피해가 30% 증가하고, 마지막 일격에 맞은 적의 강화 효과 2개를 해제한다."
- 5성 버프 2개 해제
  - 마지막 타격에 맞은 적의 강화 효과 2개를 지운다. 대상: 보호막, 공격력 증가, 피해 감소, 속도 증가.
  - 우선순위: 보호막 → 피해 감소 → 공격력 증가 → 속도 증가.
  - 적 강화 효과 목록은 1-4에서 확정한다.

**모션**
- 문제(사용자 확인): **평타 모션이 보이지 않는다.** 평타를 하지 않는 것처럼 보인다.
- 확인할 것 (이 중 어느 경우인지 원인을 적어 둔다)
  1. 평타 이벤트가 실제로 나오는지 → 전투 로그의 gwan 'hit'(skill=false)
  2. 프레임 계약에 평타 동작이 있는지
  3. 사거리나 이동 문제로 평타를 시작하지 못하는지
- 수정: 청룡언월도로 내려베기나 횡베기를 하는 평타 프레임을 연결한다. 평타가 실제로 나가지 않는다면 원인을 고친다.

**스킬 연출**
- 문제(사용자 확인): 지금은 레이저를 쏘는 것처럼 보인다(`poc/approvedSkillFx.ts:649-651` 직선 궤적, `poc/fieldView.ts:749-750` gwanWave·gwanDash·gwanImpact).
- **모션과 이펙트를 다시 만든다.**
  - 관우가 실제로 전방으로 돌진한다(이동 거리 `GWAN_SKILL_RULES.length` 유지).
  - 3번의 베기마다 언월도 궤적(초록 반달 베기)을 남긴다.
  - 마지막 베기에 맞은 적에게 방어력 감소 아이콘을 띄운다(3성 이상).
  - 직선 레이저 연출은 삭제한다.
- 피해 판정 시각은 연출의 베기 3번과 맞춘다(`GWAN_SKILL_RULES.hitTimes`).
- 원화나 이펙트 리소스가 필요하면 요청 목록에 올린다.

## 3. 나머지 83명 — 사용자 영웅별 지시가 오기 전까지의 규칙
