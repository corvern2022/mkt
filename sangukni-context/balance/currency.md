# 삼국냥전 재화 경제 감사 (commit 2e04f7f, 읽기 전용)

## 0. 방법과 표기
- 정적 분석: `src/fieldRenewal.ts`에서 import 그래프를 따라가 **실제로 도달 가능한 UI 경로**만 "LIVE"로 분류했다(`scratchpad/balance/graph.mjs`, `live.txt`). 코드는 있지만 진입 UI가 없는 경로는 "DEAD"로 표시했다(예: `openAchieveDom`, `openDungeonLegacyDom`(panels.ts:465 `void`), `openCampaignDom`, `openRankingDom`, `openEliteDungeonDom`).
- 시뮬레이션(**확정 = 실코드 시뮬**): `scratchpad/balance/sim.mts`. 실제 `game`(GameStore) 싱글톤, `contentSession`(던전), `createFieldEncounter`/`stepFieldBattle`(필드 전투·보스 판정)을 그대로 돌리고 `Date.now`만 가상 시계로 바꿨다. 보상과 비용은 전부 실제 함수가 지급하고 차감한다(`track()` 래퍼로 출처별 장부를 기록).
  - 무과금 프로필: 하루 2회 접속(09:00, 21:00), 회당 30분 플레이. D1 첫 세션은 120분. 보석은 1000개가 모이면 픽업 10연, 소환권은 초보 배너→일반 배너 순으로 사용. 금화→보석 교환은 하루 3회, 지역 상점은 전부 구매.
  - 공격력과 처치 속도는 실제 필드 전투를 40초 돌려 측정한다. 보스는 실제 보스전을 돌려 승패를 정한다. 던전은 매일 단계별로 최고+1을 실제 전투로 도전한 뒤 일일 보상을 소탕으로 받는다.
  - 두 변형: **base** = 오프라인 보상 미수령(현실적인 경우, 문제 #1 참고), **off** = 접속 직후 설정에서 오프라인 보상을 수령(최선의 경우).
  - 한계(추정 요소): UI 대기·연출 시간이 없다. 보스는 조건이 되면 즉시 도전한다. 보물 도둑은 100% 포획한다고 가정했다. 조회형 가이드 이벤트 8종(codex-view 등)은 강제로 발생시켰다. 따라서 진행 속도는 **상한에 가까운 값**이다.
- 그 밖의 숫자는 공식으로 계산했으며 **추정**으로 표시한다.

## 6. 이미 알려진 값 정정
- 가이드 소환권은 **300장**이다(18·19·33·37단계 60/60/60/120, 모두 37단계 이전). 별도로 summon 단계 진입 시 선지급 10+35장, 첫 소환 우편 10장이 있다. 전달받은 '140장(1~100단계)'은 실제 데이터와 맞지 않는다(launchGuide1000.json, referenceGuide.ts의 BEGINNER_ADVENTURE_GUIDE 런타임 합계).
- 일일 보석에는 일일퀘 외에 **일일 미션 100**(gameState.ts:1768)과 전체완료 보너스 50(2300)이 더 있다.
- 오프라인 보상은 코드상 존재하지만 실질 수령 경로가 거의 없다(#1).
