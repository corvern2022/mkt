| 새 파일 | 역할 |

| `ait-app/skill-review.html` | 진입 페이지(개발 서버 전용) |

| `ait-app/src/poc/skillReview.css` | 화면 스타일(데스크톱 3단 / 390px 1단) |
| `ait-app/src/data/heroSkillV9.json` | v9 기획 문구(85종: s0/s3/s5, 등급·직업·진영·기본공격 형태). `heroes-v9.json`에서 그대로 옮긴 데이터 |

## 적용

```bash
cd <repo>
git apply --check skill-review.patch
git apply skill-review.patch
cd ait-app
npx vite            # 기본 8080 포트
# 브라우저: http://localhost:8080/skill-review.html?hero=yeo
```

URL 파라미터: `hero`(영웅 ID), `star`(0·3·5), `enemy`(dummy·cluster·boss), `speed`(0.25·0.5·1), `allyHp`(100·60·30), `enemyHp=low`, `allies=0`(동료 제외), `auto=1`(자동 스킬).
예: `/skill-review.html?hero=jang&star=5&enemy=cluster&speed=0.5`

## 기능

- **영웅 선택**: 85종 검색(이름·ID·등급·직업·진영), 등급 필터, 등급/직업/진영 칩. 선택 시 현재 설정을 유지한 채 다시 불러옵니다.
- **스킬 설명**: v9 기획 0성/3성/5성 문구를 단계별로 보여 주고, 선택 단계에서 적용되는 줄을 강조합니다. 바로 아래에 **현재 게임 문구**(`V3_CHARACTER_BY_ID`의 active/passive/star5, 승인·런타임 문구가 합쳐진 값)를 같은 형식으로 보여 주어 v9와 다른 부분이 바로 보입니다.
- **0/3/5성 전환**: 선택 영웅의 `promotion`·`star`를 0/3/5로, 스킬 레벨은 실제 게임과 같이 `promotionSkillLevel(저장 별)`(1/4/5)로 설정합니다. 승급 피해·지원 배율(`promotionDamage`/`promotionSupport`)을 함께 표시합니다.
- **실제 전투 화면**: `mountField`(실제 필드 렌더러) + `createFieldEncounter` + `stepFieldBattle → castFieldSkill → contentBattle.cast` 그대로. 캐릭터 그림은 motion-review와 같은 경로(승인 프레임 → 리그 → 원소/소교 프로덕션 리그 → 시작 동료 시트).
  - 적 구성: 허수아비 1 / 밀집 5 / 보스 1(`chief`, 엔진의 보스 판정 적용). 적은 제자리·무반격, 체력이 매우 높아 죽지 않습니다(옵션: 적 체력 30%).
  - 아군 체력 100/60/30%(회복·보호막 확인용), 동료 2명(시작 동료, 스킬은 쓰지 않고 평타만).
  - 조작: **스킬 사용**(다음 공격 시작 때 기력 100으로 시전), **평타만 보기**(스킬 차단 + 평타 기록), **잠시 멈춤**, **속도 0.25×/0.5×/1×**, **다시 보기**(같은 설정으로 전투 재생성, 기록·미터 초기화), 자동 스킬.
- **이벤트 검사**: 시전 1회마다 실제 이벤트(`onCombatEffects`)를 묶어 표시
  - 대상별 직접 피해(시전자 공격력 대비 %, 타수별, 치명 ★), 지속 피해(화상·독 `dot`, 장판 `zoneTick`) 틱 수·기간
  - 상태 효과: 키, 값, 남은 지속시간(대상 유닛의 실제 Status에서 읽음), 화상·독은 틱당 절대량과 공격력 대비 %
  - 회복·보호막: 대상 최대체력 대비 %
  - 적중 수, 치명 수, 소환 수
  - **기대값 파일이 있으면** (`src/data/heroSkillSpec.v9.json`, 별도 패치로 제공) 선택 단계의 케이스를 읽어 효과마다 ✓/✗/?(관찰 불가·모호)를 표시합니다. 이 화면의 적 배치와 맞지 않는 케이스(체력 비율·사전 버프·피격 프로브 등 특수 조건)는 "판정하지 않은 케이스"로 따로 적습니다. 파일이 없으면 `import.meta.glob`이 빈 결과를 주므로 화면은 그대로 동작합니다.
- **피해 미터**: 아군별(소환수는 주인에게 합산) 누적 피해·회복·보호막·스킬 횟수, ‘다시 보기’까지 누적.
- 390px 폰 폭: 1단(선택 → 전투 → 설명 → 검사 → 미터), 1100px 이하 2단, 그 이상 3단.
- 디버그: `window.skillReview.{getState, records(), meter(), cast(), setStage(n), spec()}`.

## 알려진 제한

- 개발 서버 전용입니다(`vite.config.ts`의 build 입력에 넣지 않았습니다. 다른 검수 페이지와 같은 방식).
- 속도 0.25×/0.5×와 멈춤은 이 페이지에서만 `requestAnimationFrame` 시각을 가상 시계로 바꿔 구현했습니다(`fieldView`는 1/1.5/2배속만 지원). 시뮬레이션 단위와 판정 시점은 그대로이며, `performance.now()`를 직접 쓰는 일부 연출은 느려지지 않을 수 있습니다. 0.25×에서는 화면 갱신이 약 15fps가 됩니다.
- 공격력은 역할 기준값(근접 49 / 탱커 31 / 그 외 24, attackScale 1)으로 고정했습니다. 모든 수치를 **공격력 대비 %**로 보므로 비교에는 영향이 없지만, 실제 계정의 공격력·룬·장비·진영 보너스는 반영하지 않습니다.
- 피해 %는 엔진이 실제로 준 값입니다. 승급 배율(1/1.25/1.5), 3성 이상 공통 ×1.05가 포함되어 있습니다. v9 기대값 비교는 spec의 v9 성장 배율(1/1.2/1.3)을 쓰므로, 엔진이 아직 v9가 아니면 ✗가 나오는 것이 정상입니다.
- 회복량은 실제 회복량(잃은 체력이 상한)입니다. 큰 회복을 확인하려면 아군 체력 30%를 고르세요.
- 적은 반격하지 않으므로 "피격 시" 반응(반사·반격·피해 분담 등), 처치 연계, 적 버프 해제, 정화 등은 이 화면에서 직접 확인되지 않습니다(spec의 해당 케이스는 미판정으로 표시).
- 적 배치는 화면용 간단 배치(밀집 5 = 반경 약 50px)라 spec 하네스의 배치와 같지 않습니다. 대상 수는 참고용입니다.
- 필드 렌더러는 모바일 전투(`crowd=true`, 실제 게임과 동일) 조건입니다. 맵 소품이 일부 유닛을 가릴 수 있습니다.
- 헤드리스 Chromium(swiftshader)에서 큰 PNG의 `decode()`가 가끔 `EncodingError`로 실패해 `mountField` 준비가 실패하는 경우가 있었습니다(같은 파일, 같은 URL로 다시 열면 정상. motion-review에서도 같은 오류 확인). 이 화면은 필드 준비를 최대 3번까지 다시 만들고, 승인 프레임 로드가 실패하면 리그/정지 그림으로 대체합니다. 이때 `fieldView`가 남기는 콘솔 오류 1건은 그대로 보일 수 있습니다.
- 영웅을 바꾸면 그림 자원을 다시 불러오기 위해 페이지를 새로 엽니다(단계·적 구성 변경은 즉시 재시작).
