## 이 문서 읽는 법
- 1부: 공통 규칙과 초반 30분 화면 (1차 검수)
- 2부: 실제 화면을 열어 확인한 문구 (조합되어 보이는 문장, 숫자 표기)
- 3부: 나머지 화면 (던전, 장비, 생활·의뢰, 가방, 영웅, 소환, 상점, 설정 등)과 짧은 버튼명
- 4부: 가이드 46~1000단계와 2장 이후 대사
- 5부: 영웅 이름, 스킬, 상태 효과, 장비 설명
- 대사 수정은 **[제안]**으로 표시된 것만 사용자 승인이 필요하다. 나머지는 바로 적용한다.
- 앞에서 정한 공통 규칙(1부 1장)이 모든 부에 적용된다. 여러 부에 같은 항목이 나오면 같은 규칙으로 한 번만 고친다.

## 0. 먼저 고칠 것 (진행 막힘·잘못된 안내)
1. **소환 가이드 35개 단계가 막힐 수 있음 (확정)**
   - `launch-plan` 54, 112, 138, 162, 189번 등 35개 단계가 "영웅 1회 소환"을 요구한다. 준비 보상으로 주는 소환권도 1장뿐이다(`state/gameState.ts:1682`).
   - 그런데 소환은 10회 단위로만 가능하다(`summonSystem.ts:11`). 소환권 10장이나 보석 1,000이 없으면 그 단계에서 진행이 막힌다.
   - **처리:** 사용자 결정을 기다린다. 추천안은 "해당 단계를 소환이 아닌 목표로 교체(수치 불변)"이다.
2. **5번째 편성 칸 잠금 문구가 틀림.** 편성 화면에 "합류 후 해금"으로 나오지만 실제 조건은 1-6 클리어다. 4번째 칸도 화면마다 '합류', '1-4', '합류 후 해금'으로 서로 다르다.
3. **성장 던전 레벨 탭의 전투 목표가 틀림.** "레벨 획득"으로 나오지만 실제 보상은 사료다.
4. **영웅 이름 불일치.** `data/v3Characters.json`의 hahuyeon 이름이 "하후연"이다. 85명 중 유일하게 '냥'이 빠졌고, 소환 화면에는 "하후연냥"으로 나온다.
5. **받침 처리 누락.** `fieldLobby.ts:324`의 `${약초}이에요`, 생활 화면의 `${item.name}을` 등에서 이름 끝 받침에 따라 이/가, 을/를을 고르는 처리를 넣는다.
6. **같은 수치가 두 이름으로 나옴.** 영웅 상세의 '장비 회복 증폭'과 '스킬 위력'이 같은 값이다. 하나로 합친다.
7. **가이드 문구와 대사가 묶여 있음.** `fieldLobby.ts:308`에서 단아냥이 가이드 detail 문장을 그대로 읽는다. 1부에서 detail을 명사형으로 바꾸면 이 대사가 어색해지므로 두 작업을 함께 한다.

# 1부
## 1. 공통 규칙 (모든 화면)

1. **팝업에는 결과만 넣는다.**
   - 제목과 받은 것·바뀐 것만 쓴다.
   - "~하세요", "~했습니다", "~할 수 있어요" 같은 설명·지시 문장은 넣지 않는다. 오류 안내만 예외다.
2. **버튼 문구는 2~4자 동사로 쓴다.**
   - 예: 확인, 받기, 시작, 변경, 소환, 닫기
   - "이 이름으로 시작", "~회씩 연속 소환 시작" 같은 문구는 쓰지 않는다.
3. **같은 대상에는 같은 이름을 쓴다.**

| 현재 혼용 | 통일 |
|---|---|
| 몬스터 / 황건 병사 / 황건군 / 황건적(시스템 문구) | **몬스터** (대사에서는 황건적 허용) |
| 소환권 / 일반권 / 일반 소환권 / 모집권 / 영웅 모집권 | **소환권** |
| 픽업권 / 픽업 소환권 | **픽업 소환권** |
| 사료 선물상자 / 사료 상자 / 선물상자 | **사료 상자** |
| 금화 상자 / 보급 상자 | **금화 상자** |
| 호야 / 호야냥 (시스템 문구) | **호야냥** (대사에서 부르는 말은 그대로) |
| 초선 / 초선냥 | **초선냥** |
| 일반 1-1 | **1-1** ('일반' 접두어 삭제) |

4. **대사는 이야기만 담는다.** 조작 방법(어디를 눌러라, 가방에서 열어라)은 하단 가이드 문구로만 보여준다.
5. **개발·준비 상태 문구는 화면에 내지 않는다.**
   - 대상: "준비 중", "예정", "추후 안내", "기존 기록", "모의 상대", "시나리오 2 이후"
   - 판매하지 않는 상품, 지급하지 않는 기능은 항목째 숨긴다.
6. **잠금 안내는 "1-6 클리어 시 열림" 형식으로 통일한다.**
   - "가이드 N에서 ~ 열립니다"처럼 가이드 번호를 쓰지 않는다. 플레이어는 가이드 번호를 모른다.
7. **어미를 통일한다.** 시스템 문구는 명사형이나 "~니다" 단문, 캐릭터 말은 대사창에서만 쓴다. 지금은 "~요"와 "~니다"가 섞여 있다(예: "던전 증표가 모자라요").
8. **긴 규칙 설명은 기본 화면에서 뺀다.** 확률·보장 같은 내용은 [자세히] 또는 [확률 정보] 안에만 둔다.

- **'성장 던전' 이름**: 가이드·콘텐츠 정의는 '성장 던전'인데 던전 허브 카드에는 '요일 비경'이 있다. 둘이 같은 콘텐츠인지 확인하지 못했다.

## 확인 못한 것

- 실제 화면 렌더링(스크린샷)은 안 봄. 줄바꿈·잘림은 코드만 보고 판단함.
- `fieldSkills.ts` 라벨 → `partyCardStatus.ts` 역매칭이 이름을 바꾸면 깨지는지는 실행해 보지 않음(B11 주의만 적음).
- 다음 수치는 별도 처리 함수에 있어서 안 봄: 전위냥 피격 기력(0.5초 간격), 허저냥 반격 재사용, 여포냥 5성 방어력 감소, 태사자냥 두 발 명중 후속 효과, 손책냥 5성(대교냥 보호막 2배), 하후연냥 일반 공격 기력 2, 동탁냥 3·4성 효과, 관우냥 돌진 경로 피해(`gwanSkill.ts`), 공손찬냥 의병, 장비냥 보스 기절 면역(`status()` 내부).
- `data/fieldGuide.ts`의 '장료/노숙' 문구가 현재 가이드에서 실제로 나오는지(가이드 담당 범위).
- 도감·소환 결과 화면에서 등급 글자(C/N/R/SR/SSR) 옆에 따로 설명이 붙는지. C와 N의 차이를 플레이어가 알 수 있는 곳이 있는지 확인 못 함. 장비 등급(N/R/SR/SSR)과 글자가 겹치는 점도 기획 판단이 필요함.
- `heroLookout.ts`는 없음(css만 있음). 요청에 적힌 "heroLookout"은 `panels.ts` 영웅 목록/상세(`openHeroesDom`, `openHeroDetailDom`)로 보고 검수함.
- 대사(`guideStory.ts`, `fieldOpening.ts`)의 '호야/태산/단아' 호칭은 대사 규칙상 허용이라 범위 밖으로 둠.
