- **범위:** 실제 게임 진입점(`src/fieldRenewal.ts`)에서 연결되는 화면 문구 약 580개, 초반 가이드 45단계, 초반 대사 전체.
- **제외:** 스크린리더 전용 문구(aria-label). 다만 바뀐 화면 문구에 맞춰 함께 고친다.
- **대사 관련 주의:** 대사(시나리오)는 사용자 승인이 필요하다. 아래 5장은 **제안**이고, 나머지 장은 바로 적용한다.

## 1. 공통 규칙 (모든 화면)

1. **팝업에는 결과만 넣는다.**
   - 제목과 받은 것·바뀐 것만 쓴다.
   - "~하세요", "~했습니다", "~할 수 있어요" 같은 설명·지시 문장은 넣지 않는다. 오류 안내만 예외다.
2. **버튼 문구는 2~4자 동사로 쓴다.**
   - 예: 확인, 받기, 시작, 변경, 소환, 닫기
   - "이 이름으로 시작", "~회씩 연속 소환 시작" 같은 문구는 쓰지 않는다.
3. **같은 대상에는 같은 이름을 쓴다.**

| 현재 혼용 | 통일 |
|---|---|
| 몬스터 / 황건 병사 / 황건군 / 황건적(시스템 문구) | **몬스터** (대사에서는 황건적 허용) |
| 소환권 / 일반권 / 일반 소환권 / 모집권 / 영웅 모집권 | **소환권** |
| 픽업권 / 픽업 소환권 | **픽업 소환권** |
| 사료 선물상자 / 사료 상자 / 선물상자 | **사료 상자** |
| 금화 상자 / 보급 상자 | **금화 상자** |
| 호야 / 호야냥 (시스템 문구) | **호야냥** (대사에서 부르는 말은 그대로) |
| 초선 / 초선냥 | **초선냥** |
| 일반 1-1 | **1-1** ('일반' 접두어 삭제) |

4. **대사는 이야기만 담는다.** 조작 방법(어디를 눌러라, 가방에서 열어라)은 하단 가이드 문구로만 보여준다.
5. **개발·준비 상태 문구는 화면에 내지 않는다.**
   - 대상: "준비 중", "예정", "추후 안내", "기존 기록", "모의 상대", "시나리오 2 이후"
   - 판매하지 않는 상품, 지급하지 않는 기능은 항목째 숨긴다.
6. **잠금 안내는 "1-6 클리어 시 열림" 형식으로 통일한다.**
   - "가이드 N에서 ~ 열립니다"처럼 가이드 번호를 쓰지 않는다. 플레이어는 가이드 번호를 모른다.
7. **어미를 통일한다.** 시스템 문구는 명사형이나 "~니다" 단문, 캐릭터 말은 대사창에서만 쓴다. 지금은 "~요"와 "~니다"가 섞여 있다(예: "던전 증표가 모자라요").
8. **긴 규칙 설명은 기본 화면에서 뺀다.** 확률·보장 같은 내용은 [자세히] 또는 [확률 정보] 안에만 둔다.

## 4. 대사 — 시스템 안내 삭제 (바로 적용)

- **`data/guideStory.ts`의 `LAUNCH_LEARNING_NOTES` 9개를 전부 삭제한다.** 내용이 안내 문장뿐이다. "몬스터 20마리"처럼 지금 목표와 맞지 않는 숫자가 들어 있고, "이 안내를 위해 기다릴 필요는 없어요" 같은 개발용 문장도 있다. 1차 명세 C에서 이미 삭제하기로 한 항목이다.
- **`PROFILE_STORY` 3줄을 1줄로 줄인다.** 남길 대사: 단아냥 "집사님, 이름을 알려 주시겠어요?"
- **`fieldLobby.ts:318, 324, 327, 330, 333`의 안내 문장을 대사에서 뺀다.**
  - 대상: "오른쪽 설정을 열고 보스 자동 소환을 켜 주세요…", "편성에서 약초 담당을 정하세요…", "지역 생활에서 정련해…" 등
  - 이 문장들은 하단 가이드 문구로 옮긴다. 캐릭터 대사 한 줄은 남긴다.
